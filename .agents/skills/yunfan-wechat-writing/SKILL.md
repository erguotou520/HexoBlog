# 云帆在途 · 公众号写作规范

本规范从 12 篇已发布文章提炼（Octopus 网关、media-compress 升级、GPT-5.4 mini 发布、Cloudflare 故障短评、nano banana 趣玩、个人名片、小学 AI 分享会、Better DeepSeek、做公众号的感受、jd-cookie-helper、iGit、图片压缩工具）。

**职责边界**：本 skill 只产出 Markdown 正文并转换为公众号 HTML。结尾的"找到我"推广块、个人开源项目列表、署名等由公众号平台配置/用户自行添加，一律不要生成。

## 输出格式（红线）

**所有产出必须是标准 Markdown 文件（.md）。** 不直接输出 HTML——HTML 由转换脚本生成（见最后一步）。

## 文体（五类）

| 文体 | 典型文章 | 篇幅 |
|------|---------|------|
| A. 个人开源项目介绍 | `个人开源 - jd-cookie-helper`、`个人开源 - 智能 Git 工作流助手` | 中长 |
| B. 工具发布 / 升级公告 | `image-compress 升级为 media-compress`、Octopus 网关 | 中长 |
| C. 行业事件短评 | `写在Cloudflare恢复之前` | 很短（两三段） |
| D. AI 趣玩 / 生活 | `跟风来个nano banana效果`、`个人名片` | 很短（图 + 提示词） |
| E. 经历 / 感想分享 | `当AI走进小学课堂`、`开始做公众后这段时间的感受` | 中长 |

标题风格：
- A 类用系列前缀 `个人开源 - xxx`；B 类直接说结论（`image-compress 升级为 media-compress，现在支持视频压缩了`），可以起得抓人一点（`Claude + GPT + Gemini + Copilot,一个接口全部搞定,这谁顶得住?`）
- C/D/E 类口语化、随性（`写在Cloudflare恢复之前`、`跟风来个nano banana效果`）

## 按文体套结构

### A/B 类：项目介绍 / 发布公告（emoji 小节）

```
# 标题

[开头 1-2 段：痛点或缘起，第一人称、口语化。可以讲背景故事——
"做这个项目的初衷很简单——我需要一个……"，"项目上线后收到了反馈……"]

## 🛠️ 工具简介 / 项目背景
（一句话说清是什么 + 为谁解决什么问题）

## 🖼️ 预览
（有截图留图片占位）

## ✨ 核心功能 / 特性
（bullet，每条 emoji 开头 + 加粗关键词 + 一句说明）

## 🎯 使用方法 / 🚀 极简操作教程
（编号步骤，命令用代码块）

## 🔧 配置 / 技术实现细节
（可选，B 类常写，坦诚说明取舍）

## 🔗 项目地址
（GitHub 链接直接贴纯文本 URL）

## 📚 FAQ
（可选，Q1/Q2/Q3 形式）
```

### C 类：事件短评

两三段：发生了什么（时间 + 对象 + 影响）→ 为什么重要 → 自己的态度/打算。不硬凑长度。

### D 类：AI 趣玩

图 + 一句话 + 完整提示词原文。就这么多。

### E 类：经历分享

```
## 📚 导语
（3 句内概括这件事和收获）

## 一、xxx
## 二、xxx
（叙事 + 细节 + 真实感受，允许自嘲）

## 💡 后记
（升华一段，不灌鸡汤）
```

## 语气与文风

- 第一人称、口语化、坦诚：敢说缺点（"新版本比之前大了不少，原因是集成了 FFmpeg……这是没办法的事"）、敢说顾虑
- 场景化开头："先说痛点：你是不是也遇到过这些？"、"DeepSeek这段时间真的是太火啦"
- 短段落，一段一两句；多用 bullet 和表格
- 关键术语加粗；命令必须代码块
- 重要提醒用「📢 温馨提示」「⚠️ 注意」引导
- 全文中文；技术名词保留英文
- 正文写完即止，不加"欢迎关注""找到我"之类的结尾推广语

## 写作红线

- 不生成账号信息、推广块、项目列表等非正文内容
- 标题不用「震惊体」，但 B 类可以带情绪化反问
- 不编造数据：阅读量、star 数、下载量等只在用户提供时写入
- 不承诺"永久免费""绝对安全"这类绝对化表述；安全声明用事实（"数据完全本地存储，无云端同步，代码已开源"）
- 涉及灰产边界的项目描述保持克制

## 排版与发布（Markdown → 公众号 HTML）

原理逆向自 mdnice 编辑器的"复制到公众号"：公众号编辑器会剥掉 `<style>` 标签和大部分 class，**只有内联到每个元素 `style` 属性上的样式能存活**。因此转换的核心是把主题 CSS 全部内联，并把剪贴板写成 `text/html` 格式。

写完 Markdown 后依次执行：

```bash
# 1. 转换（首次运行自动安装 marked + juice 依赖，之后离线可用）
node <skill目录>/scripts/convert.mjs 文章.md

# 2. 复制到剪贴板（macOS；以 text/html 写入，公众号编辑器 Ctrl+V 即保留格式）
python3 <skill目录>/scripts/clipboard.py 文章.wechat.html
```

转换产物 `文章.wechat.html` 也可直接作为 `baoyu-post-to-wechat`（贴图/图文发布）或公众号后台粘贴的输入。

脚本做了什么（对应 mdnice 的 `ND/MD/ID` 函数）：
1. Markdown → HTML（marked）
2. 套用主题 CSS（`scripts/theme.css`，可自行替换主题）
3. juice 内联所有样式到元素 `style` 属性（`inlinePseudoElements` + `preserveImportant`）
4. 顶层元素加 `data-tool` 标记、表格加公众号草稿属性
5. 输出 html；`clipboard.py` 以 `NSPasteboardTypeHTML` 写入剪贴板（等效 mdnice 的 text/html 复制）

公式（MathJax/KaTeX）暂不支持——公众号需图片化公式，遇到时提示用户改用其它方案。
